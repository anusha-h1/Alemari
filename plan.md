# ALEMARI — Revised Implementation Plan

## Product and serving approach

Build ALEMARI (ಅಲೆಮಾರಿ) as a complete, responsive Karnataka tourism discovery, trip-planning, and personal travel-journal app for the hackathon brief “Travel & Tourism — AI Travel Planner for Karnataka.” The React/Vite/TypeScript frontend retains browser-local memories and preferences. A Python FastAPI backend now serves destination search, approximate itineraries, deterministic travel chat, and SQLite persistence for trip and memory metadata. Uploaded photos remain in browser IndexedDB; no authentication, booking provider, paid API, or external AI model is connected. Estimates are approximate; live availability and real-time prices are not connected.

## Design direction

- **Design Movement:** Luxury travel magazine meets modern interactive travel startup, rooted in Karnataka.
- **Core Principles:** Cinematic, destination-specific imagery; editorial storytelling; spacious asymmetry and refined hierarchy; real, useful local interactions.
- **Color Philosophy:** Forest green (#173D32) and deep forest (#102820) convey nature and heritage; warm cream (#F8F6F0) creates a quiet reading canvas; sand gold (#E8CD91), terracotta (#C87552), and soft sage (#DCE6D8) are restrained accents.
- **Layout Paradigm:** Large edge-to-edge hero and scroll-led editorial chapters, alternating destination stories, interactive map, and journal/calendar modules rather than a generic dashboard.
- **Signature Elements:** Compass/mountain ALEMARI mark; animated destination pins; date-stamped memory cards with subtle paper-like warmth.
- **Interaction Philosophy:** Every visible control has a meaningful action, feedback, and accessible keyboard/touch behavior. Discovery, planning, visiting, saving, and revisiting a memory connect as one journey.
- **Animation:** Subtle Framer Motion hero/reveal/card/modal/panel transitions and map-pin polish; respect reduced-motion, avoid blocking navigation, and provide a pause control for prominent moving media.
- **Typography System:** Elegant serif display headlines, clean sans-serif UI/body, and a Kannada-capable font for the Kannada wordmark/headlines; maintain strong mobile legibility.
- **Brand Essence:** A Karnataka-rooted companion for discovering places, planning trips, and keeping travel stories; curious, soulful, dependable.
- **Brand Voice:** Evocative but useful. Example: “ನಿಮ್ಮ ಮುಂದಿನ ಪಯಣ ಇಲ್ಲಿಂದ ಆರಂಭ.”; “Discover Karnataka. Experience More. Keep Every Memory.”
- **Wordmark & Logo:** Distinctive ALEMARI wordmark with compass/mountain emblem and Kannada brand name ಅಲೆಮಾರಿ.
- **Signature Brand Color:** Forest green (#173D32).

## Functional implementation

1. **Navigation and hero:** Sticky responsive navigation for Home, Discover Places, Karnataka Map, My Memories, Travel Calendar, and AI Travel Buddy, with active-section indication, favorites shortcut, mobile menu, and Plan My Trip CTA. Hero includes Kannada and English headings, specified supporting copy, Explore Karnataka / Plan My Journey / Relive My Memories actions, scroll cue, destination search, and a compact trip-planning entry with interests, budget, and days. Use a cinematic still image as a resilient baseline. Use destination-specific imagery from reliable sources (prioritizing official Karnataka tourism resources, Wikimedia Commons, Unsplash, or Pexels where appropriate), distinct images by destination, meaningful alt text, lazy loading, dark text-contrast overlays, and graceful fallbacks. Use a destination video only where an embeddable/reusable source is reliable; provide poster, muted loop/playsInline behavior, reduced-motion handling, pause control, and a static fallback. Do not depend on video playback.
2. **Discovery and storytelling:** At least 15 destination records with authentic region/district, accurate approximate coordinates, Kannada names where available, descriptions, category, recommended duration, approximate budget, and distinct photographs. Include Hampi, Coorg, Gokarna, Mysuru, Chikmagalur, Jog Falls, Badami, Udupi, Murudeshwar, Dandeli, Kudremukh, Belur, Halebidu, Pattadakal, Shivamogga, and Kabini. Add experience tiles for mountains/hills, beaches/coast, waterfalls/rivers, heritage/architecture, temples/spiritual journeys, wildlife/forests, food/culture, adventure/trekking, peaceful weekends, and hidden gems. Working search and category/region/budget filters feed the gallery. Cards show photo, name/Kannada name, location, description, tags, duration, approximate budget, favorite, details, visited, and add-to-trip actions. Add full-width editorial stories for Hampi, Coorg, and Gokarna with a working detail action. Implement Surprise Me using selected category, days, and budget; reveal a suitable real dataset destination with rationale, photo, duration, approximate budget, another suggestion, and add-to-trip action.
3. **Trip planner:** Implement a functional local wizard with (1) starting city, chosen destination or Surprise Me, start/end dates, traveller count, and available days; (2) multiple interests—nature, beaches, waterfalls, heritage, adventure, wildlife, food, spiritual, hidden gems; (3) INR budget, budget-friendly/moderate/premium style, relaxed/balanced/adventure-packed pace, transport and accommodation preferences; and (4) generated day-by-day itinerary with morning/afternoon/evening activities, suggested destinations, approximate travel/food/accommodation costs, estimated total, tips, and destination photos. Provide working regenerate, budget change, more adventurous, add hidden gems, save trip, and favorite-destination actions. Clearly disclose approximate estimates and no live pricing/availability. Persist saved trips locally and show them in the travel profile.
4. **Interactive map:** Real React Leaflet + OpenStreetMap map centered on Karnataka with destination coordinates, styled visited/unvisited pins, controls/reset, legend, search, category and visited-only filters, responsive sizing, attribution, and graceful tile/load errors. Do not fabricate a state boundary; use a suitable genuine boundary dataset only if available. Clicking a marker opens details with image, region, description, category, duration, approximate budget, visited state, and functional details/add-to-trip/mark-visited/view-memories actions. Card selection highlights its marker and marker selection highlights its card. Do not invent exact geographic boundary data.
5. **Shared local travel journal:** Typed destination, memory, photo, and trip models; one shared memory store; IndexedDB for uploaded photo blobs and larger memory records; localStorage for small preferences/favorites/visited/settings. Build add/edit/delete memory form with title, destination, visited date, multiple JPG/PNG/WebP photos, validation, previews/removal, caption, full story, favorite moment, optional rating, companions, and tags. Photos never leave the browser. Persist through refresh and show save feedback. Gallery cards show cover, destination, title, date, caption, favorite moment, and Read Story. Detail view includes full story, gallery with previous/next lightbox and practical keyboard navigation, destination/date/rating/tags, edit, and delete confirmation. Export memory metadata as JSON; confirm before clearing all memories. Keep gallery, timeline, calendar, stats and trip-related views synchronized.
6. **Calendar and timeline:** Monthly calendar with previous/next month and year navigation, Today, memory indicators/thumbnails, multiple records per day, date detail list, detail navigation, empty-day add-memory with date prefilled, past-year browsing, and calendar/timeline switch. Vertical chronological timeline includes date, destination, image, title, preview, favorite moment, location marker/line, filters by year/destination/category/favorites, newest/oldest ordering, and complete-detail action. Empty state text: “Your next adventure could become your favourite memory.” with Add First Memory action. All events derive from the shared local memory data.
7. **Alemari Mitra:** Floating friendly assistant `ಅಲೆಮಾರಿ ಮಿತ್ರ — Alemari Mitra`, animated panel/button, greeting, bubbles, suggested questions, typing indicator, scrollable session history, input/send, clear-conversation and close/reopen controls. The frontend calls the deterministic FastAPI chat endpoint and falls back to the local assistant when the API is unavailable. Recognize destinations/categories, recommend places, build simple sample itineraries, provide approximate INR ranges, consider interests/days/visited places, and avoid implying a live model is connected.
8. **Personal travel profile and footer:** Calculate places visited, memories, photos, supported districts, favorite destination, most visited category, and saved trips from local records; include My Karnataka Map shortcut filtering visited places. Footer includes requested brand/navigation and closing Kannada/English sentiment.
9. **Responsive accessibility and feedback:** Desktop-first editorial design that works on mobile, touch-friendly navigation/map/cards, accessible form labels, keyboard navigation, focus states, sufficient contrast, empty states, loading skeletons, image fallbacks, reduced-motion support, and clear success/error messages.

## Dependencies and constraints

Use stable compatible React/Vite/TypeScript, Tailwind, Framer Motion, Lucide React, React Leaflet/Leaflet, date-fns, and React Router only if useful. Use Python FastAPI and SQLite for backend API/metadata persistence; keep photo blobs and local preferences in browser IndexedDB/localStorage. Map tiles/images may require connectivity; the local assistant fallback and core discovery remain usable without the backend. Use reliable destination-specific media and distinct images; do not use watermarked, irrelevant, or repetitive placeholder photography. Keep all spend/availability figures visibly approximate.

## Project structure

- `src/app/` — application shell and section/route coordination.
- `src/components/` — navigation, hero, experience tiles, destination gallery/card/detail/story, Surprise Me, map/legend/popup, planner wizard/itinerary dashboard, memories/form/detail/lightbox, calendar, timeline, Alemari Mitra, stats/profile, footer, and reusable UI.
- `src/data/` — typed destination catalogue and categories.
- `src/hooks/` — shared local data, favorites/visited, filters, selected destination, and UI hooks.
- `src/services/` — IndexedDB/localStorage persistence, local itinerary generation, and rule-based chat service interfaces.
- `src/types/` — destination, memory, photo, trip, assistant, and filter contracts.
- `src/utils/` — search/filter, date grouping, cost/stat calculations, file validation, map helpers, and export logic.
- `src/styles/` — Tailwind, global typography/design tokens, and Leaflet presentation.
- `public/` — route manifest and static assets/fallbacks.
